# Training Module Design

## Overview
Extend the inference pipeline with a training module that mirrors the modular, configuration-driven architecture. Reuse model factory and backbone patterns. Refactor datamodule to be generic and support train/val/test splits.

## Architecture

### 1. Single Generic DataModule (`src/datamodule/`)

**Consolidate to one `JigsawDataModule` class:**
- Replace `BaseDataModule` and `InferenceDataModule` with single `JigsawDataModule`
- Handles all use cases: inference (test), training (train/val)
- Core methods:
  - `load_data(path) -> pd.DataFrame` - load CSV file
  - `get_dataloader(df, shuffle=False) -> DataLoader` - generic dataloader creation
  - `prepare_test_dataloader(test_path) -> DataLoader` - for inference
  - `prepare_train_val_dataloaders(train_path, val_path) -> (train_loader, val_loader)` - for training

**Single generic `JigsawCollator`:**
- Works for all dataset types (train/val/test)
- No training-specific logic needed
- Rename `InferenceCollator` → `JigsawCollator`

**Keep `JigsawDataset` as-is:**
- Already generic: handles any dataframe with comment_text and label

---

### 2. Create Training Module (`src/training/`)

**File Structure:**
```
src/training/
├── __init__.py
├── training_engine.py      # Main orchestrator (mirrors inference_engine.py)
├── hf_callbacks.py          # HuggingFace trainer callbacks (early stopping, etc)
└── training_args_builder.py # Helper to configure HF TrainingArguments
```

**`training_engine.py` - `TrainingEngine` class:**
- Initialize with: batch_size, max_length, num_epochs, learning_rate, warmup_steps, early_stopping_patience
- Methods:
  - `init_datamodule(tokenizer) -> JigsawDataModule`
  - `prepare_data_for_training(train_path, val_path) -> (train_loader, val_loader)` 
  - `create_trainer(model, train_loader, val_loader) -> HuggingFace Trainer`
  - `train(train_path, val_path, model_name, backbone_type, output_dir) -> None`
    - Orchestrates: tokenizer loading → model creation → datamodule setup → trainer creation → training
  - Returns: trained model saved to output_dir

**Key Design Decisions:**
- Decouple trainer from model: `Trainer(model, args, train_dataset, eval_dataset)`
- Use HuggingFace `TrainingArguments` for all hyperparameters
- Early stopping via `EarlyStoppingCallback(early_stopping_patience=3, early_stopping_threshold=0.001)`
- Save best model to output directory
- Reuse `ModelFactory.create()` for model instantiation (no changes needed)
- Reuse model configs from `config/model/`

  batch_size: 32
  max_length: 512
  num_epochs: 3
  learning_rate: 2e-5
  warmup_steps: 500
  weight_decay: 0.01

**Reuses:**
- `model` defaults from existing `config/model/` (distilbert.yaml, roberta_pretrained.yaml)
- Same project structure as inference.yaml

### 4. Data Preparation

**Assumption:** Training data is already split into `train_split.csv` and `val_split.csv` by data prep pipeline. 
- If not, create splits before training
- TrainingEngine accepts file paths, not pre-split data

---

### 5. HuggingFace Trainer Integration

**Why HuggingFace Trainer?**
- Built-in early stopping via callbacks
- Automatic validation at intervals
- Mixed precision training, gradient accumulation, distributed training support
- Standard interface in the community

**Trainer Configuration:**
```python
from transformers import Trainer, TrainingArguments
from transformers.integrations import TensorBoardCallback

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir=output_dir,
        num_train_epochs=cfg.training.num_epochs,
        per_device_train_batch_size=cfg.training.batch_size,
        per_device_eval_batch_size=cfg.training.batch_size,
        learning_rate=cfg.training.learning_rate,
        warmup_steps=cfg.training.warmup_steps,
        weight_decay=cfg.training.weight_decay,
        evaluation_strategy="steps",
        eval_steps=cfg.training.eval_steps,
        save_strategy="steps",
        save_steps=cfg.training.save_steps,
        save_total_limit=2,
        gradient_accumulation_steps=cfg.training.gradient_accumulation_steps,
        logging_steps=10,
        seed=cfg.random_seed,
    ),
    train_dataset=train_dataset,
    eval_dataset=val_dataset,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=3)],
    compute_metrics=compute_metrics_func,  # For logging metrics during training
)
```

### 6. Workflow

**User Perspective:**
```bash
./runners/run_training.sh
```

**Internal Flow:**
1. Load config (training.yaml with model defaults)
2. Initialize TrainingEngine
3. Load tokenizer for model
4. Create model via ModelFactory
5. Load train/val data via JigsawDataModule
6. Create HF Trainer with early stopping callback
7. Train model (saves checkpoints, logs metrics)
8. Save final model + training results
9. Output: trained model, metrics, logs

## Benefits of This Design

✅ **Single Generic DataModule:** One source of truth for all data loading (train/val/test)  
✅ **Reuses existing patterns:** Factory, configs, backbone abstraction  
✅ **Modular Engines:** TrainingEngine + InferenceEngine independent from models  
✅ **Extensible:** Easy to add callbacks, metrics, models  
✅ **Standard tools:** HuggingFace Trainer is battle-tested  
✅ **Configuration-driven:** All params in YAML, no code changes needed  
✅ **Early stopping:** Built-in via HF callbacks  
✅ **No duplication:** Collator and dataset work for all use cases
